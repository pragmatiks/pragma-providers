Each row records how a resource type meets the Pragmatiks findability and idempotency contract; the contract, the columns and the verdict rule are in `## Findability audit` of the repository's `CLAUDE.md`. Audited 2026-11-02 against `main@8754f36`, and the `qdrant/collection` observe refusal 2026-11-06 against `main@bc294e3`; vendor documentation read 2026-11-02.

The resource marker is the collection metadata key `pragma_resource` holding the canonical resource ID (`marker.RESOURCE_MARKER_KEY`), the key every provider uses; collection metadata is arbitrary JSON, so no vendor rule forces another spelling.

Notes:

- A collection created by a provider version before the marker carries no `pragma_resource` metadata, so a conflicting create and `on_observe` refuse it like a collection made outside Pragmatiks; pre-GA such collections are wiped, not migrated. A collection whose metadata key was removed or changed is refused the same way; restoring the key or deleting the collection outside Pragmatiks is the only recovery.
- A server older than 1.16 returns no metadata, so `config.metadata` is `None` and `marker.match_resource_marker` reads it as unmarked; `Collection.check_server_version` refuses such a server before any create, so no collection of this resource lives there.
