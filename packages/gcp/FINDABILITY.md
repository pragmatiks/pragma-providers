# Findability audit: gcp

Each row records how a resource type meets the Pragmatiks findability and idempotency contract; the contract, the columns and the verdict rule are in `## Findability audit` of the repository's `CLAUDE.md`. Audited 2026-11-02 against `main@8754f36`, and the `gcp/secret`, `gcp/gke` and `gcp/cloudsql/database_instance` observe refusal 2026-11-06 against `main@bc294e3`; vendor documentation read 2026-11-02.

The resource marker is the label `pragma_resource`, the key every provider uses (`marker.RESOURCE_MARKER_KEY`). Its value is a 62-character BLAKE2b hex digest of the resource ID (`marker.compute_resource_marker_value`), not the ID itself, because Google Cloud label values hold at most 63 lowercase letters, digits, dashes and underscores and the canonical ID holds `::` and may hold uppercase letters (https://docs.cloud.google.com/resource-manager/docs/labels-overview).

Notes:

- `run_instance_operation` waits for every pending operation on the instance before it writes, so a retried database or user create that missed its own pending insert on observe meets the finished object as a conflict and fails; that is the gap.
- Objects created by a provider version before the label carry none and are refused on a conflicting create and on observe, like objects made outside Pragmatiks; pre-GA they are wiped, not migrated. An object whose label was removed or changed is refused the same way; restoring the label or deleting the object outside Pragmatiks is the only recovery.
- The marker is advisory: it tells this resource's earlier create from an object made outside Pragmatiks or by another resource, but anyone who can write labels in the project can set it, and an object left by an earlier incarnation of the same resource ID is recognized as this resource's own.
